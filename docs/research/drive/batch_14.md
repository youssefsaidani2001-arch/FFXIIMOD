## 1. `us.lua` (TIDI English description overrides, generated by DD)

**Purpose.** This is the English (`us`, game language id 1) override table for TIDI. Each row maps a 16-bit content id
to one rich-text description string. TIDI shows that string in place of the vanilla help text when the item,
equipment piece, magick or technick is highlighted in a menu. DD generated it by walking battlepack section 13
(equipment) and section 14 (actions). So the numbers in the text are a snapshot of the battlepack that was loaded
at generation time, including any balance mods. They may not be vanilla values.

### Editor relevance

* **Offline TIDI config editor.** The exact file shape is known: a no-argument function returning `{id, "text"}`
  rows with raw decimal ids, CRLF line endings, `\n` as the only escape, and descriptions of up to 5 lines. An editor
  can round-trip this file and validate tags against the six-tag grammar and the glyph tables above.
* **Rich-text widget.** The colour set, the element and status glyph ids (icon = 21 + status bit, elements 10-17,
  flying 20) and the per-glyph scale/vpos pairs are enough to render a WYSIWYG preview. They also let an editor insert
  correctly aligned icons in any description, quest or dialog text that goes through Lua Loader `message.convert`.
* **Name/category tables.** The equipment name table (420 ids with category, type and license) and the technick table
  can be lifted straight from this file. Exact sub-range boundaries (weapons by class, guest, esper and zodiac weapons,
  shields, helms, armor, accessories by type, ammo by type) give an editor its dropdown grouping.
* **Battlepack field map.** The label set tells a section-13/14 editor which record fields matter to players: stat
  block offsets +0..+7, status/element bitfields +8..+18, power x multiplier, AOE size, MP/Mist cost, accuracy, CT,
  category byte, and the hitsFlying / canTargetFlying / canTargetUndead flags.
* **Section-14 ordering.** Content-id order in section 14 (magicks, items, arcane 0x3086/0x3051/0x3052/0x3087,
  technicks) plus 9 records with requiredContent 0xFFFF help an editor map record indices to content ids without
  hard-coding them.
* **Regeneration.** The file is generated, so an editor should change battlepack data and let DD regenerate the file,
  or edit DD's templates and i18n. Hand edits are overwritten the next time DD exports.
